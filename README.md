# HRBP HUB — макет

Интерактивный прототип HR-борда: сводка по метрикам, сводные таблицы по юнитам,
трансформеры и реестр целей (KPI) с наследованием вниз по оргструктуре.

**Живой макет:** https://romuney.github.io/HRBP_HUB/

## Как устроено

Статика без сборки — открывается как есть, локально достаточно любого
статического сервера (`python3 -m http.server`), потому что скрипты
подключаются файлами, а не модулями.

| Файл | Что внутри |
|---|---|
| `data.js` | Мок-данные: оргдерево, метрики, реестр целей и наследование, форматтеры |
| `charts.js` | Графики на ECharts: у столбиков шкала от нуля, у линий — по данным с видимой осью Y |
| `ui.js` | Общие элементы: тултип, пилюли, карточки, панели, каретки таблиц |
| `app.js` | Экраны и состояние: One-Pager, Команды, Трансформеры, Каталог, окно KPI |
| `styles.css` | Дизайн-система: токены в `:root`, компоненты собраны из них |

Внешняя зависимость одна — ECharts с CDN. Если он не загрузился, отчёт
остаётся читаемым: вместо графика выводится плашка, значения читаются в таблицах.

## Датасеты

Макет — это ещё и техзадание на данные: любой интерактив на полке фильтров
превращается в требование к грануляру витрины.

| Файл | Что внутри |
|---|---|
| `docs/dataset-spec.md` | спецификация: витрины, гранул, объёмы, что ложится на датасет, а что на дашборд |
| `sql/greenplum/` | сборка: сотрудник × период → куб по разрезам → плоская витрина с развёрткой по дереву |
| `sql/clickhouse/` | схема приёмника и атомарная публикация |
| `sql/proteus/` | виртуальный датасет с Jinja (факт + цель + база) и метрики Superset |

Порядок запуска в Greenplum — по номерам файлов: `01` оргструктура, `02`
сотрудники, `03` куб, `04` витрина, `05` цели.

## Цели и наследование

Цель ставится на юнит и действует на всю его ветку вниз. Если у потомка есть
своя цель по той же метрике — начиная с него и ниже работает она. Несколько
целей на одном юните разводятся разрезами численности (покраска, IT/nonIT,
стрим, специализация, штат/не штат, тип численности): правило применяется
только тогда, когда его разрез выбран в фильтрах отчёта.

Данные прототипа сгенерированы детерминированно и не являются фактическими
показателями.

## Публикация

GitHub Pages настроены на **Deploy from a branch → `main` / `(root)`**: макет
публикуется из корня ветки `main`, отдельной сборки нет. Всё, что попадает
в `main`, через минуту-другую оказывается на https://romuney.github.io/HRBP_HUB/

`.nojekyll` выключает обработку Jekyll — собирать нечего, а лишний шаг умеет
ронять файлы со служебными именами.
