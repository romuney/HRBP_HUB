## 00 Описание — заменить код целиком (поставка 69: таблица hrbp_hub_vac_people в описании)

```python
### HRBP HUB — витрины отчёта для HRBP

Ноут собирает всё, что нужно единственному чарту отчёта HRBP HUB в Proteus, и
выгружает в ClickHouse (`prod_proteus.hrbp_hub_*`). Метрики — числитель и
знаменатель, время — массивы по 24 слота (месяцы и недели), оргструктура —
путь юнитов в каждой строке: компания (lvl1) и lvl3…lvl12 mapped-структуры, как в
ультраширокой. Проценты не храним: любая цифра отчёта — `Σ num / Σ den`.

#### Sources
- `prod_v_emart.mdm_employee_structure_d` — база всех метрик (подневная витрина сотрудника)
- `prod_v_sse_crossdata.mdm_employee_regrettable` — разметка regrettable / non-regrettable
- `prod_v_hrmart.legal_position_dismissal_reason` — причины увольнений
- `prod_v_sse_crossdata.mdm_employee_residence` — город и макрорегион (только для трансформеров)
- `prod_v_sse_crossdata.legal_position_vacation` — накопленные дни отпуска по позиции (версии; метрика «Накопленный отпуск»)
- `prod_v_emart.legal_position_d` — позиции сотрудника на дату: неосновные (совместительство) — для пометки у метрик отпуска

#### Target (ClickHouse, база Proteus CROSS)
| Таблица | Что внутри |
|---|---|
| `hrbp_hub_cube` | путь юнита × 6 разрезов численности → массивы компонентов метрик (24 мес + 24 нед) |
| `hrbp_hub_attr` | то же × атрибут для трансформеров (грейд, стаж, город…), только месяцы |
| `hrbp_hub_attr_top` | свёртка атрибутов по всей ветке юнита без разрезов — для корней зон HRBP, компании, блоков и больших веток: трансформер открытого юнита без чтения листового куба |
| `hrbp_hub_base` | база сравнения: вся компания по 6 разрезам, без пути (строк — сколько комбинаций разрезов, тысячи) |
| `hrbp_hub_unit` | справочник юнитов: имя, уровень (1 — компания, 3…12), родитель, путь, численность сейчас, число детей, размер поддерева, есть ли свёртка атрибутов |
| `hrbp_hub_access` | логин → роль и корни зоны (RLS внутри датасета) |
| `hrbp_hub_kpi` | цели KPI (реестр правится в параграфе «KPI · реестр целей») |
| `hrbp_hub_calendar` | 48 слотов: что значит позиция в массиве |
| `hrbp_hub_nr_people` | уволенные без причины с 1 января (и свежие — «дозревает»): rk сотрудника, даты найма и увольнения, уровни 3–6, путь и разрезы — список в отчёте |
| `hrbp_hub_vac_people` | накопленный отпуск — кто в зоне на дату данных: штатные с 28+ днями по основной позиции или по совместительству; ФИО, логин, rk, найм, дни, разбивка по типам отпуска, путь и разрезы — список в отчёте |

Остаётся в GP (не выгружается, отчёт не читает): `hrbp_hub_hrbp_viewers` — HRBP → кто видит его данные
(HRBP с зоной выше, супер-HRBP, админы), вся зона или часть, руководитель ли по структуре, кто в связи старший
(в должности — «старший»). Сводка по ней — в лабе `usr_cross_data.hrbp_hub_hrbp_viewers` (параграф «Актуалайз лабы»).

#### Порядок
Параметры → календарь → строки источника → отпуска → справочник юнитов → зоны HRBP → кто видит HRBP →
увольнения → когорты найма → события по слотам → куб и база → куб атрибутов и его свёртка → цели →
проверки (падают делением на ноль) → выгрузка в ClickHouse → права → удаление времянок.

Расписание: ежедневно после обновления `mdm_employee_structure_d`.
Подробности — репозиторий HRBP_HUB, `docs/architecture.md`.
```

## 04b HH · отпуск — кто в зоне — добавить новый параграф сразу после «HH · отпуска» (поставка 69: накопленный отпуск — кто в зоне, для списка в отчёте)

```sql
-- ============================================================================
-- HH · отпуск — кто в зоне → hrbp_hub_vac_people (поставка 68, владелец 13.11: «просмотр детальных списков, кто эти
-- люди с большим количеством накопленных дней»). Строка — штатный сотрудник в численности на дату данных (текущий
-- месяц отчёта), у кого накоплено 28 дней и больше по основной позиции (жёлтая / красная зона метрик «Накопленный
-- отпуск») ИЛИ в сумме по неосновным позициям (совместительство — пометка у метрик). Те же люди и те же суммы, что в
-- hh_vac на data_dt: числа списка сходятся с метрикой (стоп-проверка 4е в «HH · проверки»).
-- Колонки (владелец 13.11): ФИО и логин (last_nm, first_nm, ad_login витрины структуры на дату данных), rk, дата
-- найма, дни по основной позиции (days) и по совместительству (xdays), разбивка основной позиции по типам отпуска
-- одной строкой (types: «код:дни|код:дни», крупные первыми, коды — как в источнике), path_s и шесть разрезов — чтобы
-- датасет отдавал людей только из юнитов зоны логина и под фильтрами отчёта, как саму метрику. Названия юнитов
-- отчёт берёт из справочника по последнему юниту пути.
-- Метрика ещё не началась (дата данных раньше vac_start_dt) — таблица пустая.
-- ============================================================================
drop table if exists hrbp_hub_vac_people;
create table hrbp_hub_vac_people as
select s.mdm_employee_rk,
       coalesce(n.fio, '')                                        as fio,
       coalesce(n.login, '')                                      as login,
       s.company_hire_dt                                          as hire_dt,
       round(v.days, 2)                                           as days,
       round(v.xdays, 2)                                          as xdays,
       coalesce(t.types, '')                                      as types,
       s.path_s, s.paint, s.it, s.stream, s.spec, s.staff, s.hct
from hh_vac v
cross join hh_param p
cross join hh_vac_start vs
join hh_src s
    on s.mdm_employee_rk = v.mdm_employee_rk and s.business_dt = v.business_dt
   and s.is_slot_row = 1 and s.hc = 1 and s.staff = 'Штат' and s.path_s <> ''
left join (
    -- ФИО и логин на дату данных; в источнике бывают дубли строк (сотрудник, день) — берём одну
    select e.mdm_employee_rk,
           max(trim(coalesce(trim(e.last_nm::text), '') || ' ' || coalesce(trim(e.first_nm::text), ''))) as fio,
           max(lower(trim(e.ad_login::text)))                                                         as login
    from prod_v_emart.mdm_employee_structure_d e
    cross join hh_param pp
    where e.business_dt = pp.data_dt
    group by 1
) n on n.mdm_employee_rk = s.mdm_employee_rk
left join (
    -- остаток основной позиции по типам отпуска на конец дня данных — тот же срез версий, что у days в «HH · отпуска»
    select q.mdm_employee_rk,
           string_agg(q.code || ':' || q.d::text, '|' order by q.d desc, q.code) as types
    from (select z.mdm_employee_rk, coalesce(nullif(trim(x.vacation_type_code::text), ''), '-') as code,
                 round(sum(x.accum_vacation_day)::numeric, 2) as d
          from (select distinct h.mdm_employee_rk, h.legal_position_rk
                from hh_src h
                cross join hh_param ph
                where h.business_dt = ph.data_dt and h.is_slot_row = 1 and h.hc = 1 and h.staff = 'Штат'
                  and h.legal_position_rk is not null) z
          cross join hh_param pz
          join prod_v_sse_crossdata.legal_position_vacation x
              on x.legal_position_rk::text = z.legal_position_rk
             and x.valid_from_dttm <= pz.data_dt + interval '1 day' - interval '1 second'
             and x.valid_to_dttm   >= pz.data_dt + interval '1 day' - interval '1 second'
          where x.deleted_flg = 0
          group by 1, 2) q
    group by 1
) t on t.mdm_employee_rk = s.mdm_employee_rk
where v.business_dt = p.data_dt
  and p.data_dt >= vs.vac_start_dt
  and (v.days >= 28 or v.xdays >= 28)
distributed by (path_s);

-- Справочно: сколько людей в списке — по зонам основной позиции и по совместительству.
select count(*)                                                 as people,
       sum(case when days >= 28 and days < 56 then 1 else 0 end) as yellow,
       sum(case when days >= 56 then 1 else 0 end)               as red,
       sum(case when xdays >= 28 then 1 else 0 end)              as sec_28plus,
       sum(case when coalesce(days, 0) < 28 then 1 else 0 end)   as sec_only,
       sum(case when fio = '' then 1 else 0 end)                 as no_fio,
       max(days)                                                 as max_days
from hrbp_hub_vac_people;
```

## 07 HH · увольнения — заменить код целиком (поставка 68: разметка regrettable — по версиям valid_from_dttm / valid_to_dttm, без business_dt; если 68-ю уже поставили — пропустить)

```sql
-- ============================================================================
-- HH · увольнения → hh_fire. Событие = строка дня увольнения из компании
-- (business_dt = company_fire_dt); юнит и разрезы — на эту дату.
--   rg / nrg — regrettable / non-regrettable: вспомогательная витрина
--              prod_v_sse_crossdata.mdm_employee_regrettable (в базе этих флагов нет). Витрина версионная
--              (13.11: valid_from_dttm / valid_to_dttm / deleted_flg, business_dt нет): флаг берётся из любой
--              неудалённой версии, живой хотя бы часть дня увольнения — valid_from < день + 1 и valid_to >= день
--              (версия, открытая днём, и версия, закрытая днём, — обе в счёт);
--   nr       — причина НЕ заполнена: legal_fire_dt не пустая, в
--              legal_position_dismissal_reason (legal_position_rk + fire_dt =
--              legal_fire_dt) нет причины — и с увольнения прошло nr_grace_days.
--              coalesce(dismissal_reason_desc, 'Причина отсутствует') = отсутствует.
--   nrd      — знаменатель незаполненных причин (Дьяченко 16.10: «не численность юнита, а все уволенные»):
--              то же, что nr, но с причиной или без — legal_fire_dt не пустая и прошло nr_grace_days.
--   Срок — по каждому уволенному от его дня увольнения (владелец 02.11: «уволился в начале месяца — к началу
--   следующего причина уже должна быть»), не по месяцу целиком. Чарт берёт месяц увольнения разностью слотов «с начала
--   года»; месяц, где срок прошёл ещё не у всех, — бледно-серым (`rip: 30` в чарте = nr_grace_days).
--   nra, nrda — то же, что nr / nrd, но БЕЗ срока: все уволенные, и свежие (поставка 54, владелец 02.11: дозревающий
--              месяц — по всем уволенным в нём, а «у скольких 30 дней прошли» — по nrd). В кубе едут в w_nr / w_nrd.
-- Дни увольнения берутся с запасом в 7 месяцев до окна: по ним когорты найма
-- узнают, дожил ли новичок до 3 и 6 месяцев.
-- ============================================================================
drop table if exists hh_fire;
create table hh_fire as
select s.mdm_employee_rk, s.company_hire_dt, s.business_dt as fire_dt,
       s.path_s, s.paint, s.it, s.stream, s.spec, s.staff, s.hct,
       s.seniority, s.a_grade, s.a_exp, s.a_gender, s.a_age, s.a_office, s.a_work, s.a_head,
       s.a_legal, s.a_macro, s.a_city, s.a_hrbp,
       coalesce(rt.rg, 0)  as rg,
       coalesce(rt.nrg, 0) as nrg,
       case when s.legal_fire_dt is not null
             and coalesce(fr.has_reason, 0) = 0
             and s.business_dt <= p.data_dt - p.nr_grace_days
            then 1 else 0 end as nr,
       case when s.legal_fire_dt is not null
             and s.business_dt <= p.data_dt - p.nr_grace_days
            then 1 else 0 end as nrd,
       case when s.legal_fire_dt is not null
             and coalesce(fr.has_reason, 0) = 0
            then 1 else 0 end as nra,
       case when s.legal_fire_dt is not null
            then 1 else 0 end as nrda
from hh_src s
cross join hh_param p
left join (
    select f.mdm_employee_rk, f.business_dt,
           max(case when r.regrettable_fire_flg = 1 then 1 else 0 end)     as rg,
           max(case when r.non_regrettable_fire_flg = 1 then 1 else 0 end) as nrg
    from (select distinct mdm_employee_rk, business_dt from hh_src where is_fire_row = 1) f
    join prod_v_sse_crossdata.mdm_employee_regrettable r
        on r.mdm_employee_rk = f.mdm_employee_rk
       and r.valid_from_dttm <  f.business_dt + interval '1 day'
       and r.valid_to_dttm   >= f.business_dt
    where r.deleted_flg = 0
    group by 1, 2
) rt on rt.mdm_employee_rk = s.mdm_employee_rk and rt.business_dt = s.business_dt
left join (
    select legal_position_rk::text as legal_position_rk, fire_dt::date as fire_dt,
           max(case when nullif(trim(dismissal_reason_desc::text), '') is not null
                     and dismissal_reason_desc <> 'Причина отсутствует' then 1 else 0 end) as has_reason
    from prod_v_hrmart.legal_position_dismissal_reason
    group by 1, 2
) fr on fr.legal_position_rk = s.legal_position_rk and fr.fire_dt = s.legal_fire_dt
where s.is_fire_row = 1
  and s.path_s <> ''
distributed by (mdm_employee_rk);
```

## 14 HH · проверки — заменить код целиком (поставка 69: стоп-проверка «4е» — список «кто в зоне» сходится с метрикой)

```sql
-- ============================================================================
-- HH · проверки. Стоп-проверки падают делением на ноль (как «Проверка на дубли»
-- в ультраширокой) — до выгрузки в ClickHouse, чтобы отчёт не получил битые
-- массивы. Последние два запроса — диагностика, ничего не роняют: их результат
-- стоит глянуть после первого запуска.
-- ============================================================================

-- 1. Дубли источника на днях, которые читает ноут: одна строка на (сотрудник, день).
select 1 / (case when count(*) > 0 then 0 else 1 end) as source_duplicates_check
from (
    select e.mdm_employee_rk, e.business_dt
    from prod_v_emart.mdm_employee_structure_d e
    join (select distinct c.slot_end as d from hh_calendar c cross join hh_param p where c.slot_end <= p.data_dt) sd
        on sd.d = e.business_dt
    group by 1, 2
    having count(*) > 1
) t;

-- 2. Короткие id узлов уникальны (первые 12 знаков md5 от rk).
select 1 / (case when count(distinct rk) = count(distinct id) and count(*) = count(distinct id) then 1 else 0 end) as unit_id_check
from hrbp_hub_unit;

-- 3. Все массивы куба — ровно 24 позиции.
select 1 / (case when count(*) > 0 then 0 else 1 end) as cube_array_length_check
from hrbp_hub_cube
where array_length(m_hc, 1) <> 24 or array_length(w_hc, 1) <> 24
   or array_length(m_hcw, 1) <> 24 or array_length(w_r6ad, 1) <> 24
   or array_length(m_vr, 1) <> 24 or array_length(w_vr, 1) <> 24
   or array_length(m_vxr, 1) <> 24 or array_length(w_vxr, 1) <> 24;
select 1 / (case when count(*) > 0 then 0 else 1 end) as attr_array_length_check
from hrbp_hub_attr
where array_length(m_hc, 1) <> 24 or array_length(m_r6ad, 1) <> 24 or array_length(m_vr, 1) <> 24;
select 1 / (case when count(*) > 0 then 0 else 1 end) as attr_top_array_length_check
from hrbp_hub_attr_top
where array_length(m_hc, 1) <> 24 or array_length(m_r6ad, 1) <> 24 or array_length(m_vr, 1) <> 24;

-- 3б. Свёртка атрибутов = листовой куб: свёртки верхних узлов дерева (pid = '') вместе —
--     это весь куб юридической численности (свёртка — «без разрезов», 13.10); по каждому атрибуту сходятся
--     численность, увольнения и накопленный отпуск (штатные и их остаток, 11.11) за все месяцы.
select 1 / (case when count(*) > 0 then 0 else 1 end) as attr_top_equals_leaf_check
from (
    select coalesce(l.attr_k, t.attr_k) as attr_k
    from (select x.attr_k, sum(x.hc) as hc, sum(x.fire) as fire, sum(x.vacd) as vacd, sum(x.vac) as vac
          from (select attr_k, unnest(m_hc) as hc, unnest(m_fire) as fire, unnest(m_vacd) as vacd, unnest(m_vac) as vac
                from hrbp_hub_attr a cross join hh_param pr where a.hct <> pr.nonlegal_type) x
          group by 1) l
    full join (select x.attr_k, sum(x.hc) as hc, sum(x.fire) as fire, sum(x.vacd) as vacd, sum(x.vac) as vac
               from (select a.attr_k, unnest(a.m_hc) as hc, unnest(a.m_fire) as fire, unnest(a.m_vacd) as vacd, unnest(a.m_vac) as vac
                     from hrbp_hub_attr_top a
                     join hrbp_hub_unit u on u.id = a.unit_id and u.pid = '') x
               group by 1) t
        on t.attr_k = l.attr_k
    where coalesce(l.hc, -1) <> coalesce(t.hc, -1) or coalesce(l.fire, -1) <> coalesce(t.fire, -1)
       or coalesce(l.vacd, -1) <> coalesce(t.vacd, -1) or coalesce(l.vac, -1) <> coalesce(t.vac, -1)
) d;

-- 4. Куб сходится с источником: численность на конец последнего закрытого месяца.
select 1 / (case when c.hc = s.hc then 1 else 0 end) as cube_headcount_check, c.hc as cube_hc, s.hc as source_hc
from (
    select sum(k.m_hc[l.pos]) as hc
    from hrbp_hub_cube k
    cross join (select c.idx + 1 as pos
                from hrbp_hub_calendar c
                join hh_param p on c.grain = 'm' and c.slot_end = p.last_month_end) l
) c
cross join (
    select count(*) as hc
    from hh_src s join hh_param p on s.business_dt = p.last_month_end
    where s.is_slot_row = 1 and s.hc = 1 and s.path_s <> ''
) s;

-- 4б. База сходится с кубом: вся компания без пути = сумма куба (месяцы и недели,
--     численность и знаменатель текучести) и массивы по 24 позиции.
select 1 / (case when b.m_hc = c.m_hc and b.w_hc = c.w_hc and b.m_hcw = c.m_hcw and b.bad = 0 then 1 else 0 end) as base_equals_cube_check,
       b.m_hc as base_hc, c.m_hc as cube_hc
from (
    select sum(k.m_hc[l.pos]) as m_hc, sum(k.w_hc[24]) as w_hc, sum(k.m_hcw[l.pos]) as m_hcw,
           sum(case when array_length(k.m_hc, 1) <> 24 or array_length(k.w_r6ad, 1) <> 24 then 1 else 0 end) as bad
    from hrbp_hub_base k
    cross join (select c.idx + 1 as pos
                from hrbp_hub_calendar c
                join hh_param p on c.grain = 'm' and c.slot_end = p.last_month_end) l
) b
cross join (
    select sum(k.m_hc[l.pos]) as m_hc, sum(k.w_hc[24]) as w_hc, sum(k.m_hcw[l.pos]) as m_hcw
    from hrbp_hub_cube k
    cross join (select c.idx + 1 as pos
                from hrbp_hub_calendar c
                join hh_param p on c.grain = 'm' and c.slot_end = p.last_month_end) l
) c;

-- 4г. Уволенные без причины (поставка 56) сходятся с метрикой: всей компании с начала года — с прошедшими 30 днями
--     столько же, сколько m_nr базы в последнем месяце, всех (и свежих) — сколько w_nr.
select 1 / (case when p.r = b.r and p.a = b.a then 1 else 0 end) as nr_people_check,
       p.r as people_ripe, b.r as base_nr, p.a as people_all, b.a as base_nr_all
from (select coalesce(sum(ripe), 0) as r, count(*) as a from hrbp_hub_nr_people) p
cross join (
    select coalesce(sum(k.m_nr[l.pos]), 0) as r, coalesce(sum(k.w_nr[l.pos]), 0) as a
    from hrbp_hub_base k
    cross join (select c.idx + 1 as pos
                from hrbp_hub_calendar c
                join hh_param p on c.grain = 'm' and c.slot_end = p.last_month_end) l
) b;

-- 4д. Накопленный отпуск (11.11) сходится с «HH · отпуска»: на конец последнего месяца штатные в численности (vacd),
--     их остаток в сотых долях дня (vac) и люди в жёлтой / красной зоне (vy / vr) — в кубе, в базе и в hh_vac одно и
--     то же; если метрика ещё не началась (покрытие ниже порога) — везде нули. С 12.11 — и штатные, у кого сумма по
--     неосновным позициям в жёлтой / красной зоне (vxy / vxr, sec_*).
select 1 / (case when c.d = s.d and c.v = s.v and c.y = s.y and c.r = s.r and c.xy = s.xy and c.xr = s.xr
                  and b.d = s.d and b.v = s.v and b.y = s.y and b.r = s.r and b.xy = s.xy and b.xr = s.xr
             then 1 else 0 end) as vac_check,
       s.d as src_staff, c.d as cube_staff, s.v as src_vac, c.v as cube_vac, s.y as src_yellow, c.y as cube_yellow,
       s.r as src_red, c.r as cube_red, s.xy as sec_yellow, c.xy as cube_sec_yellow, s.xr as sec_red, c.xr as cube_sec_red
from (
    select coalesce(sum(k.m_vacd[l.pos]), 0) as d, coalesce(sum(k.m_vac[l.pos]), 0) as v,
           coalesce(sum(k.m_vy[l.pos]), 0) as y, coalesce(sum(k.m_vr[l.pos]), 0) as r,
           coalesce(sum(k.m_vxy[l.pos]), 0) as xy, coalesce(sum(k.m_vxr[l.pos]), 0) as xr
    from hrbp_hub_cube k
    cross join (select c.idx + 1 as pos
                from hrbp_hub_calendar c
                join hh_param p on c.grain = 'm' and c.slot_end = p.last_month_end) l
) c
cross join (
    select coalesce(sum(k.m_vacd[l.pos]), 0) as d, coalesce(sum(k.m_vac[l.pos]), 0) as v,
           coalesce(sum(k.m_vy[l.pos]), 0) as y, coalesce(sum(k.m_vr[l.pos]), 0) as r,
           coalesce(sum(k.m_vxy[l.pos]), 0) as xy, coalesce(sum(k.m_vxr[l.pos]), 0) as xr
    from hrbp_hub_base k
    cross join (select c.idx + 1 as pos
                from hrbp_hub_calendar c
                join hh_param p on c.grain = 'm' and c.slot_end = p.last_month_end) l
) b
cross join (
    select coalesce(sum(o.ison), 0) as d,
           coalesce(sum(o.ison * round(v.days * 100)), 0) as v,
           coalesce(sum(o.ison * case when v.days >= 28 and v.days < 56 then 1 else 0 end), 0) as y,
           coalesce(sum(o.ison * case when v.days >= 56 then 1 else 0 end), 0) as r,
           coalesce(sum(o.ison * case when v.xdays >= 28 and v.xdays < 56 then 1 else 0 end), 0) as xy,
           coalesce(sum(o.ison * case when v.xdays >= 56 then 1 else 0 end), 0) as xr
    from hh_vac v
    join hh_param p on v.business_dt = p.last_month_end
    cross join (select case when p.last_month_end >= s.vac_start_dt then 1 else 0 end as ison
                from hh_param p cross join hh_vac_start s) o
) s;

-- 4е. Список «кто в зоне» (поставка 69) сходится с метрикой: на дату данных в hrbp_hub_vac_people жёлтая / красная зона по
--     основной позиции — столько же людей, сколько m_vy / m_vr базы в последнем месяце, по совместительству — m_vxy / m_vxr;
--     в списке нет никого вне зон (у каждого 28+ хотя бы по одной из сумм).
select 1 / (case when p.y = b.y and p.r = b.r and p.xy = b.xy and p.xr = b.xr and p.bad = 0 then 1 else 0 end) as vac_people_check,
       p.n as people, p.y as people_yellow, b.y as base_yellow, p.r as people_red, b.r as base_red,
       p.xy as people_sec_yellow, b.xy as base_sec_yellow, p.xr as people_sec_red, b.xr as base_sec_red, p.bad as people_out_of_zone
from (select count(*) as n,
             coalesce(sum(case when days >= 28 and days < 56 then 1 else 0 end), 0) as y,
             coalesce(sum(case when days >= 56 then 1 else 0 end), 0) as r,
             coalesce(sum(case when xdays >= 28 and xdays < 56 then 1 else 0 end), 0) as xy,
             coalesce(sum(case when xdays >= 56 then 1 else 0 end), 0) as xr,
             coalesce(sum(case when coalesce(days, 0) < 28 and coalesce(xdays, 0) < 28 then 1 else 0 end), 0) as bad
      from hrbp_hub_vac_people) p
cross join (
    select coalesce(sum(k.m_vy[l.pos]), 0) as y, coalesce(sum(k.m_vr[l.pos]), 0) as r,
           coalesce(sum(k.m_vxy[l.pos]), 0) as xy, coalesce(sum(k.m_vxr[l.pos]), 0) as xr
    from hrbp_hub_base k
    cross join (select c.idx + 1 as pos
                from hrbp_hub_calendar c
                join hh_param p on c.grain = 'm' and c.slot_end = p.last_month_end) l
) b;

-- 4в. Глубина пути: компания + не больше 10 уровней (lvl3…lvl12).
select 1 / (case when max(array_length(path, 1)) <= 11 then 1 else 0 end) as path_depth_check,
       max(array_length(path, 1)) as max_path_len
from hrbp_hub_cube;

-- 5. Каждый узел из путей куба есть в справочнике.
select 1 / (case when count(*) > 0 then 0 else 1 end) as cube_units_in_dictionary_check
from (select distinct unnest(path) as id from hrbp_hub_cube) x
left join hrbp_hub_unit u on u.id = x.id
where u.id is null;

-- 6. Доступ не пуст: хотя бы один HRBP с зоной.
select 1 / (case when count(*) > 0 then 1 else 0 end) as access_not_empty_check
from hrbp_hub_access where role in ('hrbp', 'super');

-- Диагностика: строки без юнита (в отчёт не попадают), увольнения без разметки
-- regrettable, незаполненные причины; правила KPI, не попавшие в отчёт.
select (select count(*) from hh_src where path_s = '')                     as rows_without_unit,
       (select count(*) from hh_fire)                                        as fires,
       (select count(*) from hh_fire where rg = 0 and nrg = 0)               as fires_without_regret_marking,
       (select count(*) from hh_fire where nr = 1)                           as fires_without_reason,
       (select count(*) from hrbp_hub_cube)                                  as cube_rows,
       (select count(*) from hrbp_hub_attr)                                  as attr_rows,
       (select count(*) from hrbp_hub_base)                                  as base_rows,
       (select count(*) from hrbp_hub_unit where is_current = 1)             as units_now,
       (select count(distinct login) from hrbp_hub_access)                   as logins;
select r.rule_id, r.unit_rk, r.metric_id,
       case when u.id is null then 'нет такого юнита' else 'неизвестная метрика или пустая цель' end as problem
from hh_kpi_src r
left join hrbp_hub_unit u on u.rk = trim(r.unit_rk)
where u.id is null
   or trim(r.metric_id) not in ('retention_new_3', 'retention_new_6', 'regret', 'exit_reasons', 'jun_team', 'vac_yellow', 'vac_red')
   or r.target is null;

-- Диагностика отпусков (11.11): с какого месяца метрика в отчёте (vac_start_dt; 5999-01-01 — ни один месяц не набрал
-- порог покрытия), покрытие штатных записями об отпуске в последнем месяце и сколько месяцев после начала ниже порога
-- (их отчёт показывает — проверить источник; помесячно — таблица hh_vac_cov).
select s.vac_start_dt,
       (select c.cov from hh_vac_cov c where c.slot_end = p.last_month_end)                          as vac_cov_now,
       p.vac_min_cov,
       (select count(*) from hh_vac_cov c where c.slot_start >= s.vac_start_dt and c.cov < p.vac_min_cov) as vac_low_months
from hh_vac_start s
cross join hh_param p;
```

```sql
-- ============================================================================
-- Диагностика источников (выключен, запускать руками после первого прогона).
-- Отвечает на открытые вопросы business-context.md и filter-fields.md: какие
-- значения у разрезов на самом деле, покрытие regrettable-разметки, есть ли у
-- всех увольнений строка в день увольнения. Результаты — владельцу отчёта.
-- ============================================================================

-- 1. Значения разрезов численности в срезе (сверить с подписями отчёта).
select 'paint' as cut, paint as value, count(*) as hc from hh_src s join hh_param p on s.business_dt = p.data_dt where s.hc = 1 group by 1, 2
union all select 'it', it, count(*) from hh_src s join hh_param p on s.business_dt = p.data_dt where s.hc = 1 group by 1, 2
union all select 'staff', staff, count(*) from hh_src s join hh_param p on s.business_dt = p.data_dt where s.hc = 1 group by 1, 2
union all select 'hct', hct, count(*) from hh_src s join hh_param p on s.business_dt = p.data_dt where s.hc = 1 group by 1, 2
union all select 'seniority', s.seniority || ' → джун ' || coalesce(j.jun, 0)::text, count(*)
          from hh_src s join hh_param p on s.business_dt = p.data_dt left join hh_seniority j on j.seniority = s.seniority
          where s.hc = 1 group by 1, 2
order by 1, 3 desc;

-- 1а. Тип численности против флага активной численности и статуса «в списочной» (hc) в
--     срезе: «Активная» должна совпасть с active_employee_flg = 1; строки с hc = 0 — уволенные
--     или ещё не нанятые, в численность не идут ни при каком типе.
select hct, hc_act as active_employee_flg, hc as in_list, count(*) as rows_n
from hh_src s join hh_param p on s.business_dt = p.data_dt
group by 1, 2, 3
order by 4 desc;

-- 1б. Юридическая численность против типа (HRBP 13.10): строки legal_employee_flg <> 1 отчёт кладёт в тип
--     «Вне юр. численности» (без выбранного типа их нет). Если у них встречается «Активная» — при выборе
--     «Активная» эти люди не попадут: сообщить, решим отдельно.
select coalesce(e.legal_employee_flg, 0) as legal_employee_flg, e.active_type_nm, count(*) as rows_n
from prod_v_emart.mdm_employee_structure_d e
join hh_param p on e.business_dt = p.data_dt
group by 1, 2
order by 1, 3 desc;

-- 1в. Приход в активную численность по месяцам (HRBP 13.10): найм в компанию с типом «Активная», переходы
--     кандидатов, внутренние переводы — сверить с ожиданием HRBP.
select date_trunc('month', e.business_dt)::date as month,
       sum(case when coalesce(e.company_hire_flg, 0) = 1 and lower(trim(e.active_type_nm)) = lower(trim(p.active_type_value)) then 1 else 0 end) as hire_active,
       sum(case when coalesce(e.candidate_transfer_flg, 0) = 1 then 1 else 0 end) as candidate_transfer,
       sum(case when coalesce(e.internal_transfer_flg, 0) = 1 then 1 else 0 end)  as internal_transfer,
       sum(case when coalesce(e.company_hire_flg, 0) = 1 then 1 else 0 end)       as hire_company
from prod_v_emart.mdm_employee_structure_d e
cross join hh_param p
where e.business_dt >= date_trunc('year', p.data_dt) - interval '1 year'
group by 1
order by 1;

-- 2. Регrettable-разметка по месяцам увольнения: доля размеченных.
select date_trunc('month', fire_dt)::date as fire_month,
       count(*)                                    as fires,
       sum(rg)                                     as regrettable,
       sum(nrg)                                    as non_regrettable,
       sum(case when rg = 0 and nrg = 0 then 1 else 0 end) as not_marked,
       sum(nr)                                     as reason_missing
from hh_fire
group by 1
order by 1;

-- 3. Увольнения без строки в день увольнения: company_fire_dt есть в более ранней
--    строке, а строки на сам день нет. Должно быть 0 — иначе событие теряется.
select count(*) as fires_without_fire_day_row
from (
    select distinct e.mdm_employee_rk, e.company_fire_dt
    from prod_v_emart.mdm_employee_structure_d e
    join hh_param p on e.business_dt = p.last_month_end
    where e.company_fire_dt between (select min(slot_start) from hh_calendar) and p.data_dt
) f
left join hh_fire h on h.mdm_employee_rk = f.mdm_employee_rk and h.fire_dt = f.company_fire_dt
where h.mdm_employee_rk is null;

-- 4. Разметка regrettable вне дня увольнения (витрина версионная, 13.11): неудалённые версии с regrettable_fire_flg = 1,
--    ни одна из которых не жива в день увольнения этого сотрудника. Если таких много — разметка ставится позже
--    увольнения (версия открывается в день разметки), и «HH · увольнения» её теряет: сообщить, сдвинем правило.
--    days_after — медиана дней от последнего увольнения до начала такой версии.
select count(*)                                                       as regret_versions_total,
       sum(case when x.on_day = 0 then 1 else 0 end)                  as regret_versions_not_on_fire_day,
       percentile_cont(0.5) within group (order by x.days_after)      as days_after_median
from (
    select r.mdm_employee_rk, r.valid_from_dttm,
           max(case when r.valid_from_dttm < h.fire_dt + interval '1 day' and r.valid_to_dttm >= h.fire_dt then 1 else 0 end) as on_day,
           min(case when h.fire_dt <= r.valid_from_dttm::date then r.valid_from_dttm::date - h.fire_dt end)              as days_after
    from prod_v_sse_crossdata.mdm_employee_regrettable r
    left join hh_fire h on h.mdm_employee_rk = r.mdm_employee_rk
    where r.regrettable_fire_flg = 1
      and r.deleted_flg = 0
      and r.valid_from_dttm >= (select min(slot_start) from hh_calendar)   -- версии, открытые в окне отчёта (hh_fire — с запасом 7 мес)
    group by 1, 2
) x;
```
