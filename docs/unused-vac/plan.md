# HRBP HUB · метрика «Накопленный отпуск» (unused_vac) — решения и план

Обновлено: 11.11.2026. Исходная инструкция — «emart_add_vacation_to_structure.md».
Метрика была отложена (`docs/business-context.md` § 2.6) до доработки источника — этот план её возвращает.

## Решения владельца (11.11)

- **Источник** — `prod_v_sse_crossdata.legal_position_vacation` в **GP** (та же витрина, что в DLH). Ноут — как все параграфы HRBP HUB.
- **Версии бизнесовые**, история за 24 месяца есть. Версия на дату — **состояние на конец дня**: `deleted_flg = 0` и `valid_from_dttm <= d 23:59:59 <= valid_to_dttm`. `valid_to` включительный — следующая версия начинается через 1 секунду (этап 0, запрос 2: 1,49 млн стыков «+1 сек», 3 дыры); дублей на концах месяцев нет (запрос 3). Срез по датам «от `valid_from::date` до `valid_to::date`» не годится — терял бы позицию в день окончания версии.
- **Срез** — как месяцы отчёта: закрытый месяц — на последний день, текущий — на дату данных (вчера).
- **Численность** — по фильтрам отчёта, по умолчанию «Активная».
- **Только штатные** (11.11): и числитель, и знаменатель — штатные сотрудники (`employment_relation_type_desc =
  'Штатный сотрудник'` = значение «Штат» разреза `staff`), какой бы разрез ни был выбран — как активная HQ у текучести.
  Без этого нештатные (у них отпусков нет) занижали бы долю.
- **Позиция** — пока только основная (`legal_position_rk` строки `mdm_employee_structure_d`).
- **Остаток** — сумма `accum_vacation_day` по всем типам. Разбивки по типам в метрике нет — позже, в деталях по сотруднику.
- **Метрика — доля сотрудников в зоне** (две метрики, «лучше — ниже»):
  - жёлтая зона — накоплено 28 ≤ дни < 56;
  - красная зона — 56 дней и больше.
- **Начало истории — по покрытию** (11.11): в ранних месяцах структура есть, а отпусков ещё нет. Метрика начинается с
  первого месяца, где записи об отпуске есть хотя бы у **85 %** штатных по компании (`hh_param.vac_min_cov` = 0.85);
  месяцы раньше — пустые (все компоненты 0 → в чарте «нет данных», «Год к году» — «—»), а не нулевые доли. Порог —
  в общих параметрах; дозагрузят историю — начало сдвинется само. Месяц после начала с покрытием ниже порога —
  не прячем, печатаем в диагностике (параграф 14).
- **Дробные дни** отображаются. В кубе остаток хранится в сотых долях дня (целым: 7,33 → 733), чарт делит на 100.

## Знаменатель и вид

- Знаменатель долей — **вся штатная численность** (владелец 11.11). Штатный без записи об отпуске — «не в зоне», как
  сотрудник без большого остатка (у штатного запись должна быть всегда). Запрос 5 этапа 0 (`pct_cov`) — только сверка
  полноты источника, на знаменатель не влияет.
- Выбран разрез «Не штат» — у метрик «—» и пометка в строке метрики «считается только по штатным» (`rowNote`, как норматив HQ).
- «Жёлтая» / «красная» — в названиях метрик; цвет ячеек — как у всех метрик: сравнение с KPI или базой.

## Компоненты (num / den)

| Колонка | Что | Для чего |
|---|---|---|
| `vacd` | штатная численность на конец месяца (`hc` строки со `staff` = «Штат») | знаменатель обеих долей |
| `vy` | штатные в жёлтой зоне (28 ≤ дни < 56) | числитель «жёлтой» |
| `vr` | штатные в красной зоне (≥ 56) | числитель «красной» |
| `vac` | Σ остатков штатных, сотые доли дня | средний остаток в подсказке / «О метрике» (можно убрать, если не влезет бюджет SQL) |
| `vacx` *(на будущее)* | люди, у кого по НЕосновным позициям накоплено > 30 дней | показывать неосновные позиции только таким |

## На будущее — неосновные позиции

По умолчанию — только основная позиция. Неосновные (совместительство) берутся из `legal_position` по `mdm_employee_rk`;
отображаются, только если у сотрудника по неосновным позициям накоплено больше 30 дней. Место под параграф и колонку
закладывается сразу; как показывать — проработать отдельно.
