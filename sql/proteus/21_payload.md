# Контракт payload: что запрос отдаёт фронту

Отрисовка своя — ECharts и HTML макета, — поэтому датасет не
подстраивается под чарт. Он отдаёт один контракт, а разбирает его фронт.
Ниже — что именно приезжает, каким запросом и что с этим делает JS.

## Метрики запроса — всегда две

```
sum(value_num)
sum(value_den)
```

Больше ничего в SQL не считается. Отклонение, светофор, дельты, формат —
на фронте, код уже написан в `data.js` и `ui.js`.

**Агрегация обязательна.** Запрос идёт в агрегатном режиме, не «сырыми
записями»: в витрине строка — это комбинация шести разрезов, и без
`GROUP BY` на каждую клетку таблицы уедет по 10–20 строк.

## Запрос на вкладку

Один датасет, но у каждой вкладки своя группировка. Запрос привозит
сразу всё, что вкладке может понадобиться, — включая ряды для графиков,
которые появятся только после клика.

| Вкладка | `GROUP BY` | Фильтр | Строк |
|---|---|---|---|
| One-Pager | `row_kind, target_unit_id, metric_id, period_start` | `grain in ('month','week')` | ~400 |
| Команды | `row_kind, target_unit_id, child_unit_id, grandchild_unit_id, metric_id, period_start` | `grain = 'month'` | ~9 300 |
| Трансформеры | `row_kind, cut_value, metric_id, period_start` | `row_kind = 'fact'`, `grain = 'month'` | ~1 100 |

`target_unit_id` стоит в группировке всегда: у строк факта он пустой
и ничего не дробит, а без него цели схлопнулись бы в одну сумму.

Временной фильтр на дашборде — **«No filter»**. Окно задаёт витрина
(18 месяцев / 24 недели), а у строк цели периода нет: фильтр по диапазону
дат выкинул бы их молча.

## Три вида строк

| `row_kind` | Ключ | `value_num` / `value_den` | Кто читает |
|---|---|---|---|
| `fact` | `child_unit_id`, `grandchild_unit_id`, `metric_id`, `period_start` | числитель / знаменатель | все цифры и графики |
| `bench` | `metric_id`, `period_start` | то же по всей компании | база сравнения |
| `target` | `target_unit_id`, `metric_id` | цель / 1 | ориентир, ★ Фокус, «Только фокусные» |

Колонки, общие для всех трёх: `grain`, `period_start`, адреса юнита,
шесть разрезов, паспорт метрики (`metric_name`, `metric_short`,
`metric_better`, `metric_fmt`, `metric_unit`, `is_ratio`, `out_scale`).
У целей дополнительно `target_owner_name`, `target_inherited`,
`target_is_own`.

## Что делает фронт

```js
// 1 · значение — как в макете, отношение сумм
const value = m.is_ratio
  ? m.out_scale * sum(rows, 'value_num') / sum(rows, 'value_den')
  : sum(rows, 'value_num');

// 2 · узел −1 и строка ИТОГО — свёртка узлов −2.
//     num/den аддитивны, строк десятки: материализовать это в витрине
//     значило бы 2,3× объёма ради сложения полусотни чисел.
const child = rollup(factRows, r => r.child_unit_id);

// 3 · ориентир — существующий baselineFor(): есть цель → сравниваемся
//     только с ней, иначе с базой; абсолютные метрики не сравниваются
const bl = baselineFor(unitPath, metricKey, value, state);

// 4 · дельты — из соседних точек ряда, без лагов в витрине
const { mom, yoy } = deltas(series);
```

Соответствие функциям прототипа, которые остаются как есть:

| Что | Функция в макете |
|---|---|
| свёртка листьев/узлов | `aggMetricLeaves` |
| выбор цели или базы | `baselineFor`, `resolveKpi` |
| светофор и мёртвая зона ±5% | `stateForKpi`, `compareState`, `statesOver` |
| формат чисел и дельт | `fmtVal`, `fmtDelta`, `deltaClass` |
| MoM / YoY | `deltas` |
| недельный ряд | приходит из витрины (`grain = 'week'`), `weeklyOf` больше не нужен |

Единственная функция прототипа, которая уходит: `weeklyOf` —
в макете она разворачивала недели из месяцев, чтобы два полотна не
спорили. В проде недельный ряд считается из тех же фактов и приезжает
своим гранулом.

## Справочник юнитов

Дерево (`hrbp.dim_unit`, ~3 000 строк) фронт грузит один раз отдельным
запросом и держит в памяти. Из него: отступы в списках, путь юнита
в шапке, `childrenOf` / `ancestorsOf` для свёртки и раскрытия, пометка
«● на юните стоит своя цель».

## Что перезапрашивается

**Только смена фильтров на полке**: разрезы численности, юнит, HRBP,
набор метрик, разрез на Трансформерах.

Всё остальное — раскрытие строки метрики, клик по юниту, раскрытие
до узла −2, переключение «Год / 12 недель», тумблер «Только фокусные» —
работает по уже загруженным данным. Это и есть причина, по которой
запрос тянет больше, чем видно на экране.

Исключение по бюджету: недельный гранул на вкладке «Команды» удваивает
ответ, а переключатель масштаба — явное действие. Там один перезапрос
уместнее лишних десяти тысяч строк в каждом ответе.
