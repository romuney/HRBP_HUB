# Контракт payload: что запрос отдаёт фронту

Отрисовка своя — ECharts и HTML макета, — поэтому датасет не
подстраивается под чарт. Он отдаёт один контракт, а разбирает его фронт.

Главное отличие от обычной витрины: **периода в контракте нет**. Окно
фиксировано, пользователь его не выбирает, поэтому время свёрнуто
в массивы, и одна строка несёт сразу оба гранула.

## Массивы

| Поле | Длина | Что в слотах |
|---|---|---|
| `num_m`, `den_m` | 24 | 0–11 — прошлый календарный год, 12–23 — текущий |
| `num_w`, `den_w` | 24 | 0–11 — предыдущие 12 недель, 12–23 — последние 12 закрытых |

Массивы **позиционные**: длина и порядок — часть контракта, сдвиг на один
элемент молча переставит весь ряд. Форма проверяется и в Greenplum,
и `CONSTRAINT`ом в ClickHouse.

`den` работает ещё и **маской присутствия**: `den[i] = 0` значит «в этом
слоте значения нет» — месяц ещё не закрыт, либо не из чего считать долю
(никого не наняли). В этом месте фронт рисует разрыв, а не ноль.
У абсолютных метрик `den[i] = 1` там, где слот закрыт.

Что откуда берётся, одним взглядом:

```
слоты месяцев:  0 ─────────── 11 │ 12 ─────────── 23
                прошлый год       │ текущий год, хвост пустой
график «год к году»  = две половины массива как есть
спарклайн «12 мес»   = последние 12 закрытых слотов
Δ мес                = i и i−1
Δ год                = i и i−12          ← тот же месяц год назад

слоты недель:   0 ─────────── 11 │ 12 ─────────── 23
                предыдущие 12     │ последние 12 закрытых
график «12 недель к предыдущим 12» = две половины массива
```

## Метрики запроса — четыре

```
sumForEach(num_m)   sumForEach(den_m)
sumForEach(num_w)   sumForEach(den_w)
```

Поэлементное сложение — и есть агрегация. Работает потому же, почему
работает вся модель: числитель и знаменатель аддитивны, поэтому
`SUM/SUM` на любом уровне честен, а «среднего средних» не возникает
ни на одном шаге.

**Агрегация обязательна.** Запрос идёт в агрегатном режиме, не «сырыми
записями»: в витрине строка — это комбинация шести разрезов, и без
`GROUP BY` на каждую клетку таблицы уедет по 10–20 строк.

Если сборка Proteus не отдаёт массивы в чарт-дату — обернуть в строку
(`arrayStringConcat(sumForEach(num_m), ',')`) и распарсить на фронте.
Это стоит проверить до того, как будет собран весь дашборд.

## Запрос на вкладку

Один датасет, но у каждой вкладки своя группировка. Запрос привозит
сразу всё, что вкладке может понадобиться, — включая ряды для графиков,
которые появятся только после клика.

| Вкладка | `GROUP BY` | Строк |
|---|---|---|
| One-Pager | `row_kind, target_unit_id, metric_id` | ~30 |
| Команды | `row_kind, target_unit_id, child_unit_id, grandchild_unit_id, metric_id` | ~1 000 |
| Трансформеры | `row_kind, cut_value, metric_id` | ~70 |
| Каталог метрик | `metric_id` + счётчик целей | 10 |

`target_unit_id` стоит в группировке всегда: у строк факта он пустой
и ничего не дробит, а без него цели схлопнулись бы в одну сумму.

Строк стало на порядок с лишним меньше, чем при грануле «строка на
период», и, что важнее, **исчезло дублирование измерений**: имена юнитов,
метрик и разрезов больше не повторяются 24 раза подряд.

Временного фильтра на дашборде нет вообще — в датасете нет колонки даты.
Раньше это был отдельный риск (фильтр по диапазону тихо выкидывал строки
целей), теперь его нет по построению.

## Три вида строк

| `row_kind` | Ключ | В массивах | Кто читает |
|---|---|---|---|
| `fact` | `child_unit_id`, `grandchild_unit_id`, `metric_id` | числитель / знаменатель | все цифры и графики |
| `bench` | `metric_id` | то же по всей компании | база сравнения |
| `target` | `target_unit_id`, `metric_id` | цель / маска её действия | ориентир, ★ Фокус, «Только фокусные» |

Общие колонки: адреса юнита, шесть разрезов, паспорт метрики
(`metric_name`, `metric_short`, `metric_better`, `metric_fmt`,
`metric_unit`, `is_ratio`, `out_scale`). У целей дополнительно
`target_owner_name`, `target_inherited`, `target_is_own`.

Цель — тоже ряд, а не число. Это не усложнение: контракт становится
одинаковым для всех трёх веток, а линия цели на графике получает историю
бесплатно. Поменяли цель в мае — на графике ступенька, а не задним числом
переписанное прошлое.

## Что делает фронт

```js
// 1 · поэлементное сложение — вся агрегация, которая осталась на фронте
const addInto = (acc, arr) => {
  for (let i = 0; i < arr.length; i++) acc[i] += arr[i];
  return acc;
};

// 2 · значение в слоте: den = 0 значит «данных нет», а не «ноль»
const at = (row, i) => row.den[i]
  ? (row.is_ratio ? row.out_scale * row.num[i] / row.den[i] : row.num[i])
  : null;

// 3 · ряд для графика — срез массива, а не новый запрос
const prevYear = idx => idx.slice(0, 12);
const curYear  = idx => idx.slice(12, 24);
const win12    = (idx, last) => idx.slice(last - 11, last + 1);

// 4 · узел −1 и строка ИТОГО — свёртка узлов −2 тем же addInto
const child = rollup(factRows, r => r.child_unit_id);

// 5 · дальше всё как в макете
const bl = baselineFor(unitPath, metricKey, value, state);
const { mom, yoy } = deltas(series);
```

Соответствие функциям прототипа, которые остаются как есть:

| Что | Функция в макете |
|---|---|
| свёртка узлов | `aggMetricLeaves` → поэлементное сложение массивов |
| выбор цели или базы | `baselineFor`, `resolveKpi` |
| светофор и мёртвая зона ±5% | `stateForKpi`, `compareState`, `statesOver` |
| формат чисел и дельт | `fmtVal`, `fmtDelta`, `deltaClass` |
| MoM / YoY | `deltas` — теперь по индексам `i−1` и `i−12` |
| ряды «год к году» и «12 недель» | срезы массива вместо `prevYearOf` / `curYearOf` / `weeklyOf` |

`weeklyOf` уходит совсем: в макете она разворачивала недели из месяцев,
чтобы два полотна не спорили. Теперь недельный ряд приходит из витрины,
посчитанный из тех же фактов.

## Два маленьких справочника

Фронт грузит их один раз и держит в памяти:

* **`dim_period`** — 48 строк: границы и подписи слотов, признак «слот
  закрыт». Без него позиция в массиве ничего не значит. Отсюда же фронт
  берёт индекс последнего закрытого месяца — не угадывая его по данным.
* **`dim_unit`** — дерево юнитов (~3 000 строк): отступы в списках, путь
  юнита в шапке, `childrenOf` / `ancestorsOf` для свёртки и раскрытия,
  пометка «● на юните стоит своя цель».

## Что перезапрашивается

**Только смена фильтров на полке**: разрезы численности, юнит, HRBP,
набор метрик, разрез на Трансформерах.

Всё остальное локально: раскрытие строки метрики, клик по юниту,
раскрытие до узла −2, тумблер «Только фокусные» и — теперь уже без
оговорок — переключение «Год / 12 недель». Оба гранула лежат в одной
строке, переключатель не ходит в базу.
